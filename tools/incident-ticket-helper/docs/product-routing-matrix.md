# Product and Service Routing Matrix

## Purpose

This matrix provides a recommended technical escalation path based on the affected product or service.

The matrix is a training and documentation aid. Analysts must follow current internal procedures, service ownership rules, and supervisor guidance before escalating a live incident.

## Escalation Workflow

1. Identify the affected product or service.
2. Select it in the Incident Ticket Helper.
3. Review the recommended category and target team.
4. Validate severity, impact, and urgency.
5. Confirm the escalation path using current internal procedures.
6. Document the reason for escalation and troubleshooting completed.
7. Include the target team in the generated incident chronology.

## Governance Note

This matrix should be reviewed whenever:

- Team responsibilities change.
- A product is moved to a different support group.
- A new service is introduced.
- Escalation delays or incorrect routing are identified.
- Internal procedures are updated.
